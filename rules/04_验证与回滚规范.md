# 验证与回滚规范

## 应用前校验

- 源文件必须存在于输入项目内；
- 目标路径必须位于输出目录内；
- 输出目录不存在时由 harness 创建；
- 写入目标文件前必须记录文件快照，包括文件是否存在及原始字节内容。

## 应用后验证

- Python 文件使用 AST 语法解析验证；
- 其他文件验证存在性与可读性；
- 后续接入编译、单元测试等验证时，必须全部通过才算成功。
- 可在 `verification` 配置导入检查与白名单命令，收尾阶段统一执行；
- `verification.target_python` 指定目标解释器时，依赖与导入检查必须
  使用该解释器；未指定时使用运行迁移工具的当前 Python；
- 启用行为验证但没有实际检查项时状态必须为 `unverified`，不得记作
  通过，也不得把整体质量评估标记为成功；
- `fail_on_error: true` 时行为验证失败必须让任务进入 `failed`，
  并保留 `report.md` 中的失败项。

## 回滚规则

- 验证失败时恢复写入前的文件快照，不得直接删除已有成功修改；
- 目标文件原本存在时恢复原内容，原本不存在时才删除新文件；
- 将计划条目标记为 `failed`；
- 记录失败原因与回滚动作；
- 未验证通过的计划不得记为 `applied`。

## 完成条件

- 全部计划条目处理完成；
- 审计状态保存到 `state.json`；
- 最终生成中文迁移报告。
