# 配置说明

配置文件为项目根目录的 `config.yaml`，修改后重启 CLI 生效。
项目采用模板模式：`config.example.yaml` 入库，`config.yaml` 被
`.gitignore` 忽略。首次使用请复制：

```powershell
Copy-Item config.example.yaml config.yaml
```

`load_config` 在 `config.yaml` 缺失时会自动回退到
`config.example.yaml`，方便测试与克隆后直接运行。

## LLM 配置

```yaml
llm:
  provider: openai
  temperature: 0.2
  max_tokens: 2048
  timeout_seconds: 120

  openai:
    base_url: https://api.openai.com/v1
    api_key_env: OPENAI_API_KEY
    model: gpt-4o-mini

  ollama:
    base_url: http://localhost:11434
    model: qwen2.5:7b
```

`provider` 支持 `openai` 与 `ollama`。`openai` 表示任何兼容
OpenAI 协议的服务。DeepSeek 示例：

```yaml
llm:
  provider: openai
  openai:
    base_url: https://api.deepseek.com/v1
    api_key_env: DEEPSEEK_API_KEY
    model: deepseek-chat
```

API Key 通过环境变量提供，不写入配置文件。

DeepSeek 的切换方式：在 `openai` 段取消注释
`base_url`、`api_key_env`、`model` 三行，并设置
`DEEPSEEK_API_KEY` 环境变量。

## 迁移档案配置

```yaml
migration:
  # 迁移档案: 由 migration/profile_defs/*.yaml 定义
  profile: py2to3
  # 改动类别范围: syntax | deprecated_api
  scope: syntax
```

档案决定 transform 规则与默认知识库；未传 `--docs` 时，
主循环自动加载当前档案对应的 `knowledge_base/<profile>/`。

命令行可以覆盖配置文件：

```powershell
.venv\Scripts\python.exe main.py `
  --profile langchain_community `
  --scope deprecated_api `
  --agentic
```

`--docs` 会在档案默认知识库之外追加文档，不覆盖默认目录。

## 检索配置

```yaml
retrieval:
  bm25:
    enabled: true
    top_k: 20

  vector:
    enabled: false
    top_k: 20
    embedding_model: paraphrase-multilingual-MiniLM-L12-v2
    chroma_path: kb/chroma

  rerank:
    enabled: false
    top_k: 5
    model: cross-encoder/ms-marco-MiniLM-L-6-v2
```

向量检索依赖 `sentence-transformers`，未安装时需保持 `enabled: false`。
PDF 文档解析依赖 `pypdf`，未安装时导入包含 PDF 的来源会提示安装。

## 行为验证

```yaml
verification:
  enabled: false
  timeout_seconds: 120
  target_python: ""
  required_files: []
  required_packages: []
  import_modules: []
  commands: []
  fail_on_error: true
```

启用后，会在收尾阶段对输出目录执行：

- `required_files` 中的输出文件存在性检查；
- `required_packages` 中使用目标解释器执行依赖包安装检查；
- `import_modules` 中使用目标解释器执行模块导入检查；
- `commands` 中的白名单命令，不支持 shell 语法，工作目录为输出目录。

`target_python` 留空时，依赖和导入检查使用运行迁移工具的当前
Python。填写目标项目解释器后，这两类检查统一切换到该解释器。
`commands` 始终按配置原样执行，不会自动替换其中的 Python 路径。

Python 命令必须包含 `-c`、`-m` 或脚本路径；只写一个 Python 解释器
会被拒绝，避免进入交互式 REPL 后长时间挂起。

`fail_on_error: true` 时任一验证失败会使任务进入 `failed`，失败项仍会
写入 `report.md`；设为 `false` 时只记录验证结果，不终止任务。

启用行为验证但未配置任何文件、依赖、导入或命令检查时，状态为
`unverified`。它不会终止迁移任务，但整体质量评估不会判定为成功。

### 解释器归属

| 配置项 | 使用的解释器 | 依赖安装位置 |
| --- | --- | --- |
| `required_packages` | `target_python`，为空时使用当前 Python | 对应解释器所在环境 |
| `import_modules` | `target_python`，为空时使用当前 Python | 对应解释器所在环境 |
| `commands` | 命令中显式指定的解释器 | 该解释器所在环境 |

如果目标项目有自己的虚拟环境，可以直接配置：

```yaml
verification:
  enabled: true
  target_python: "D:\target-project\.venv\Scripts\python.exe"
  required_files:
    - app.py
  required_packages:
    - fastapi
  import_modules:
    - app
  commands:
    - '"D:\target-project\.venv\Scripts\python.exe" -m pytest -q'
  fail_on_error: true
```

所有检查的工作目录都是迁移输出目录。`import app` 会加载迁移后的
`app.py`；`commands` 中的解释器需要显式写出目标项目路径。

## 护栏配置

```yaml
guardrails:
  allowed_tools:
    - scan_files
    - retrieve_examples
    - propose_plan
    - apply_patch
    - run_verifier
    - write_report

  auto_apply_max_impact: low
  require_approval_impact:
    - medium
    - high

  # 重构比例超过该值必须征得用户同意
  max_refactor_ratio: 0.3

  deny_extensions:
    - .pyc
    - .pdb
    - .exe
    - .dll
    - .so
    - .dylib
    - .bin
    - .dat

  max_file_size_mb: 5

  excluded_dirs:
    - .git
    - node_modules
    - __pycache__
    - venv
    - .venv
    - dist
    - build
    - .migration-agent

  # 输出目录允许预先存在的目录；其他内容会在启动前被拒绝
  allowed_output_entries:
    - .venv
    - venv
    - .git
    - .migration-agent
```

### 输出目录预置内容

输出目录不存在或为空时可以直接开始迁移。如果输出目录已经存在，
则只能包含 `allowed_output_entries` 中声明的目录，例如目标项目的
`.venv`。源码、配置或其他未声明内容会使任务在启动前被拒绝，避免
新旧文件混合后产生错误的验证结果。

如果必须使用完全空目录，可以配置：

```yaml
guardrails:
  allowed_output_entries: []
```
