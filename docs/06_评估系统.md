# 评估系统

## 目的

评估系统用于回答一个核心问题：**每次改动后，检索和迁移质量是变好了还是
变坏了。** 它通过固定的 Golden 期望答案，对真实执行结果打分，作为回归基线。

## 运行方式

基线模式（默认，无需 LLM，也不读取任何真实迁移结果）：

```powershell
.venv\Scripts\python.exe -m evals.run
```

真实模式（读取一次真实迁移输出的 `state.json`，评估真实工具轨迹
与已应用的语义编辑）：

```powershell
.venv\Scripts\python.exe -m evals.run --state 输出目录\.migration-agent\state.json
```

也可单独传入真实编辑提案：

```powershell
.venv\Scripts\python.exe -m evals.run --edit-proposals proposals.json
```

`proposals.json` 是编辑提案数组，字段与 `apply_edit` 的 `item` 一致
（`file`、`start_line`、`end_line`、`new_content`、`evidence`），
顺序需与 `evals/golden/edit.json` 的 `cases` 一一对应。

对已有迁移输出目录做质量评估：

```powershell
.venv\Scripts\python.exe -m evals.run --quality-output D:\migrated
```

完整评估报告保存为 JSON 文件，默认写入 `evals/reports/`
（可按时间戳区分，也可用 `--output` 指定路径）；控制台只打印保存路径
与四模块摘要，不再输出完整 JSON。

评估过程不调用 LLM API，只依赖本地模型权重（向量/重排）与已有的
state 或提案文件，因此可以离线运行。

## 评估内容

### 1. 检索质量

- Golden 数据：`evals/golden/retrieval.json`；
- 覆盖 `py2to3` 与 `py3_upgrade` 两套知识库，分别按档案加载文档；
- 每条记录为“查询 → 期望命中的文档 ID”；
- 指标：
  - recall@K：期望文档被召回的比例；
  - nDCG@K：按排名加权的命中质量；
  - MRR：第一个正确命中的倒数排名；
- 按当前配置运行，可对比 BM25、向量与混合检索。

### 2. 迁移规则

- Golden 数据：`evals/golden/migration.json`；
- 每条记录为“迁移前源码 → 期望迁移后源码”；
- 支持 `expected`（精确相等）与 `contains`（包含关键片段）两种断言；
- 指标：用例通过率。

### 3. Agentic 编排

- Golden 数据：`evals/golden/agentic.json`；
- 每条记录包含期望的工具调用序列；
- 指标：
  - tool_accuracy：工具选择准确率；
  - sequence_match：序列是否完全一致；
  - completion：是否正常完成；
  - violation_count：白名单外调用次数；
- 真实运行后传 `--state` 会自动从审计记录提取实际工具序列再评估；
  未传时以 golden 期望序列为基线自检；
- `finish` 是终止动作，不计入 violation_count。

### 4. 语义编辑质量

- Golden 数据：`evals/golden/edit.json`；
- 每条记录为“期望的文件、行范围与替换内容”；
- 指标：
  - edit_accuracy：编辑提案是否与 golden 完全一致；
  - evidence_ok：是否携带证据；
- 未提供提案时以 golden 自身为基线，`evidence_ok` 显示 `null`；
- 传 `--state` 或 `--edit-proposals` 时使用真实 LLM 生成的提案，
  此时 `evidence_ok` 才参与判定。

### 5. 规则覆盖度

- Golden 数据：`evals/golden/rules.json`；
- 按 golden case 的 `profile` 加载全局规则与档案专属规则，比较实际
  检测到的 API 与期望集合；
- 指标：
  - recall：期望 API 中被规则命中的比例；
  - missing：规则未覆盖的 API；
  - extra：规则检测到但不在期望集合中的 API；
- 该评估不依赖 LLM，用于防止规则包新增或修改后出现覆盖回退。

### 6. 迁移质量

通过 `--quality-output` 指定迁移输出目录时，会评估：

- Python 文件 AST 语法通过率；
- 按当前档案规则扫描后的未修复信号数量；
- `verification` 配置的文件、依赖、import 与命令验证结果；
- overall_success：语法全部通过、无未修复信号、行为验证全部通过。

### 7. 真实 LLM 端到端评估

使用 `--e2e` 会实际启动 Agentic 迁移流程，在临时输出目录中完成一次
真实迁移，然后复用迁移质量评估检查结果：

```powershell
.venv\Scripts\python.exe -m evals.run `
  --e2e `
  --e2e-source examples\semantic_big_demo `
  --e2e-output evals\e2e_runs\semantic
```

可选参数：

- `--e2e-profile` / `--e2e-scope`：指定迁移档案与范围；
- `--e2e-docs`：追加知识文档；
- `--e2e-command`：迁移后执行行为验证命令；
- `--e2e-target-python`：指定目标项目解释器，用于依赖与导入检查。

评估结果包含耗时、阶段、计划条目、应用/失败数量、未修复信号和
`overall_success`。该评估需要真实 LLM API，默认不运行，CI 也不会执行。

## 当前基线

- 检索：两套档案 avg recall@5 = 1.0，avg nDCG@5 ≈ 0.604，
  avg MRR ≈ 0.473；
- 迁移：5/5 通过；
- Agentic：golden 期望序列默认满分，violation_count = 0；
- 语义编辑：golden 基线默认满分，基线模式不判定证据。
- 规则覆盖：示例 API 集合 avg recall = 1.0。

## 扩展方式

- 新增检索用例：往 `retrieval.json` 增加查询与期望文档；
- 新增迁移用例：往 `migration.json` 增加 Before/After；
- 新增 Agentic 场景：往 `agentic.json` 增加场景与期望序列；
- 新增语义编辑用例：往 `edit.json` 增加期望编辑。
- 新增规则覆盖用例：往 `rules.json` 增加示例路径与期望 API 集合。
