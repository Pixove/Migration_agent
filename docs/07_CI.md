# 持续集成

项目通过 GitHub Actions 自动运行测试与评估，配置文件位于
`.github/workflows/ci.yml`。

## 触发条件

- 推送到任意分支；
- 创建或更新 Pull Request。

## 执行内容

CI 在 Python 3.11、3.12、3.13 三个版本上分别执行：

1. 安装 `requirements-ci.txt` 中的基础依赖；
2. 运行全部单元测试：
   `python -m unittest discover tests -v`；
3. 运行评估系统：
   `python -m evals.run --output evals/reports/ci-eval.json`；
4. 上传评估报告为构建产物。

## 为什么使用轻量依赖

CI 不安装 `sentence-transformers`、`chromadb` 等重型向量依赖。
`config.example.yaml` 默认关闭向量检索与重排，因此测试和评估可以
在没有模型缓存的环境中稳定运行。

CI 也不会运行 `evals.run --e2e`，因为真实端到端迁移需要 LLM API 和
外部网络，应由开发者手动执行。

本地开发仍然使用完整 `requirements.txt`，以启用混合检索能力。

## 本地复现

```powershell
python -m pip install -r requirements-ci.txt
.venv\Scripts\python.exe -m unittest discover tests -v
.venv\Scripts\python.exe -m evals.run --output evals\reports\ci-eval.json
```

## 失败处理

- 单元测试失败：修复代码或测试后重新推送；
- 评估失败：查看上传的 `ci-eval.json`；
- 规则覆盖或检索指标回退：检查对应规则、知识库和检索配置。
