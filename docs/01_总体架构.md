# 总体架构

## 分层结构

```text
入口层      main.py                 CLI 参数与交互输入
配置层      config.yaml             LLM、检索、护栏、工作区配置
编排层      agent/loop.py           主循环与阶段编排
护栏层      agent/guardrails.py     路径沙箱、白名单、预算、审批
状态层      agent/state.py          状态机、计划条目、审计记录
工具层      tools/                  扫描、补丁、验证、报告
检索层      retrieval/              文档导入、BM25、向量、重排
策略层      AGENTS.md rules/ skills/ 行为与技能说明
输出层      输出目录/.migration-agent/ 报告与审计
```

## 数据流

```mermaid
flowchart LR
    A["用户输入两条路径"] --> B["main.py 加载配置"]
    B --> C["MigrationRunner 初始化护栏"]
    C --> D["扫描输入项目"]
    D --> E["导入文档并混合检索"]
    E --> F["LLM 生成迁移计划"]
    F --> G["校验与审批"]
    G --> H["应用补丁到输出目录"]
    H --> I["验证输出"]
    I --> J["生成报告与审计"]
```

## 关键设计原则

1. 模型只负责提出方案，harness 负责校验、执行与验证；
2. 输入项目只读，输出目录是唯一可写区域；
3. 工具调用必须经过白名单；
4. 每条迁移决策必须有证据；
5. 验证失败立即回滚；
6. 所有关键动作写入审计记录。

## 演进方向

当前 `MigrationRunner` 以固定流水线调用工具函数；后续将升级为
Agent 决策循环：LLM 通过 `ToolDispatcher` 按需调用白名单工具，
`agent/loop.py` 继续负责状态机、护栏与审计，skills 与 rules
通过 `context_loader` 进入模型上下文。
