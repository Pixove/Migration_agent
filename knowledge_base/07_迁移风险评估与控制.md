# 迁移风险评估与控制

## 背景

企业级迁移必须控制风险：变更越小、证据越明确、验证越充分，
回归概率越低。

## 影响面分级

- `low`：单文件、局部语法或 API 替换，可自动应用；
- `medium`：涉及文件间依赖或语义调整，需要人工审批；
- `high`：跨模块重构、删除代码或架构调整，必须人工审批。

## 大规模重构阈值

当计划中 `transform` 涉及的行数超过项目总行数的 30% 时，
必须暂停并征得用户明确同意，Agent 不允许自行豁免。

## 证据要求

每条修改计划必须引用知识库检索命中，`evidence` 中的文档 ID
必须真实存在于检索结果，禁止编造依据。

## 最小变更

- 一次只处理计划声明的目标；
- 禁止顺手重构无关代码；
- 禁止跨文件变更，除非计划明确声明并经审批。

## 审计

所有计划、应用结果、验证结果、审批记录写入输出目录下的
`.migration-agent/`，确保可追溯。

## 注意事项

风险控制优先于迁移速度；无法验证的变更不应进入输出。
