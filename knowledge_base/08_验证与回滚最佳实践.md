# 验证与回滚最佳实践

## 背景

迁移输出必须经过验证才能视为成功，验证失败必须回滚，不能带病交付。

## 语法验证

Python 文件迁移后立即执行 AST 解析：

```python
import ast
ast.parse(source)
```

语法错误说明迁移规则存在缺陷，应回滚并修正规则。

## 编译检查

```python
compile(source, filename, 'exec')
```

## 单元测试

- 迁移前记录测试基线；
- 迁移后运行完整测试套件；
- 新行为差异（如整数除法、编码）单独补充用例。

## diff 审查

- 检查 diff 是否只包含计划声明的变更；
- 检查是否出现意外删除或格式大面积变动；
- 检查注释与文档字符串是否被误改。

## 回滚规则

- 验证失败时删除输出文件并标记 `failed`；
- 记录失败原因与回滚动作；
- 未验证通过的计划不得标记为 `applied`。

## 前后对比

保留迁移前后输出对比，便于人工审查：

- 变更行数与 diff；
- 行为测试结果；
- 性能与内存基线（可选）。

## 注意事项

验证是 harness 的硬门槛，不允许跳过或人为标记通过。
