# 并发安全最佳实践

## 背景

遗留系统常通过线程共享全局状态。GIL 只保证字节码级原子性，
不能保证业务逻辑原子性，迁移并发代码时必须显式加锁或使用并发容器。

## 共享状态

Before:

```python
counter = 0

def increment():
    global counter
    counter += 1
```

After:

```python
import threading

lock = threading.Lock()
counter = 0

def increment():
    global counter
    with lock:
        counter += 1
```

风险：`counter += 1` 不是原子操作，多线程下会丢失更新。

## 锁的使用

- 使用 `with lock:` 避免忘记释放；
- 读多写少场景考虑 `RLock` 或读写锁；
- 加锁顺序必须全局一致，否则产生死锁；
- 避免在持锁期间调用可能阻塞或回调的业务代码。

## 队列与线程池

Before:

```python
import Queue
q = Queue.Queue()
```

After:

```python
import queue
from concurrent.futures import ThreadPoolExecutor

q = queue.Queue()

with ThreadPoolExecutor(max_workers=4) as executor:
    results = list(executor.map(process, items))
```

## 竞态检查清单

- 是否有共享可变对象；
- 读改写操作是否加锁；
- 集合、计数器、缓存是否线程安全；
- 是否可能出现死锁或活锁；
- 测试是否覆盖并发路径。

## 注意事项

并发迁移后应做压力测试与竞态检测，不能只靠单元测试；
优先减少共享状态，而不是堆更多锁。
