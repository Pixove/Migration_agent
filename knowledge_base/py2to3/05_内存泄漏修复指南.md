# 内存泄漏修复指南

## 背景

遗留系统常出现内存持续增长，常见原因包括引用环、无界缓存、
全局注册表和未释放资源。

## 引用环

Before:

```python
class Node:
    def __init__(self):
        self.parent = None
        self.children = []
```

After:

```python
import weakref

class Node:
    def __init__(self):
        self.parent = None
        self.children = []
```

父节点引用子节点、子节点引用父节点会形成环，无法被引用计数回收；
单向引用或使用 `weakref` 可打破环。

## __del__ 陷阱

依赖 `__del__` 清理资源并不可靠，可能在解释器关闭时才执行。

Before:

```python
class Session:
    def __del__(self):
        self.close()
```

After:

```python
class Session:
    def close(self):
        ...

    def __enter__(self):
        return self

    def __exit__(self, *args):
        self.close()
```

## 无界缓存

Before:

```python
cache = {}

def get(key):
    return cache.setdefault(key, compute(key))
```

After:

```python
from functools import lru_cache

@lru_cache(maxsize=256)
def get(key):
    return compute(key)
```

风险：缓存 key 无上限时会持续占用内存，必须设置容量或淘汰策略。

## 全局注册表

回调、监听器、连接池写入全局列表后忘记移除，会导致对象无法回收。
应在对象生命周期结束时显式注销。

## 资源句柄

文件、socket、数据库连接必须使用 `with` 或 `try/finally` 关闭；
迁移后检查所有 `open`、`connect` 的配对关闭。

## 排查方法

- 使用 `tracemalloc` 对比快照；
- 使用 `gc.get_objects()` 检查异常增长对象；
- 对疑似泄漏路径做长时间运行测试。
